Coral Hub: privacy information

This page describes the Coral Hub service we operate at app.coralhub.dev. It does not apply to a hub you host yourself using coral --hub (see Run your own hub). On this page, “the hub” means Coral Hub (the hosted service at app.coralhub.dev).

Coral Hub is in closed beta. This page describes how the hub handles your data. It is a technical disclosure written in plain language, not legal advice. It is about Coral Hub only: the Coral app privacy policy covers the Coral desktop app.

Last updated: 15 October 2026. Coral Hub is in closed beta; this information may change, and we will update the date when it does.

The short version

  • Coral Hub can read what passes through it. When you open a terminal, chat or file from one of your Coral servers in the hub, the content travels from your server to the hub and on to your browser. Both connections use TLS, but the hub is the end of each one, so it can read the content while it passes through. This is not end-to-end encryption.
  • Coral Hub does not save that content. It is held in memory while it is being relayed and is not written to the database, the logs or disk.
  • Coral Hub does save a small amount of account information, listed below.

What the hub keeps in memory briefly

To show your agents in one list, the hub keeps a short summary of each connected server's agents in memory (names, status, branch, a short summary, token counts; at most 500 live agents plus up to 200 archived ones per server, about 1.25 MiB in all). If a server's connection drops, the hub keeps only presence (name and status, not summaries, prompts, paths or commands) for 10 minutes and then forgets it. None of this is written to disk or the database. A signed-in session's account id and email are also held in memory for a few seconds, so the hub does not have to read the database on every request (a short session cache); nothing new is written anywhere.

What passes through the hub but is not stored

Terminal output and the keys you type, chat messages, file contents and listings, agent prompts, task and board data, and the requests used to launch agents. Hub logs record only that a request happened (method, route name, result, size, duration), never its content, its query string or any credential.

If you are not comfortable with a service operated by someone else being technically able to read this traffic while it is in transit, do not connect that Coral server to the hub. Local Coral keeps working without the hub.

Messages between your own Coral servers (team messaging)

This applies only if you turn on team messaging for your account. It is off by default, for every account, until you switch it on in Coral Hub.

  • What it does. When team messaging is on and you have linked two teams, the hub passes a message from a team on one of your Coral servers to a team on another of your Coral servers. This happens between your machines, without a browser open, and the hub can read the message while it passes through.
  • It does not store the message. The message is held in memory only while it is being delivered. It is not written to the database, the logs or disk, and there is no queue. To stop duplicates, the hub keeps the sender's message id (not the content) in memory for 10 minutes. If the receiving server is offline, the message is refused, the sender is told it failed, and it can send the message again.
  • Links are yours to control. A message can only go along a link you created, from one named team to one named team. A link works in one direction only (you can approve both directions in one step, which creates two links). You can revoke a link, or switch team messaging off, at any time; revoking takes effect on the next message.
  • Notices to both teams. When you create or revoke a link, Coral Hub posts a short notice to the message boards of both teams (for example, "You can now message homelab/platform (via Coral Hub)"). The text is fixed and written by Coral; nothing is stored for it, and if a server is offline the notice is not delivered later.
  • A machine can ask where it may send. A Coral server can ask the hub which teams a given team is linked to. The hub answers with only the addresses you approved for that team. It is not a directory: it does not list your other servers or teams.
  • Servers in your account only. A message can only reach a server in your own account.

We do not sell this data. We do not use it for advertising. We do not store payment information in the hub.

Cookies

Three cookies, all strictly necessary, all Secure and HttpOnly. __Host-coral_hub_session keeps you signed in. __Host-coral_hub_pre (about an hour) is used during sign-in to make sure the link or OAuth reply returns to the same browser. __Host-coral_next (10 minutes) is set only when you open a dashboard link while signed out. It remembers which page you were opening, so sign-in can take you back to it; it holds only a path on the hub, is used once, and is then cleared. All three are host-only: the browser sends them to the hub's own address and to no other. No tracking or advertising cookies. The Coral Hub web app at app.coralhub.dev loads no third-party scripts, fonts or images. The pages of this website (not the hub app) are served through Cloudflare, which sets one security cookie, __cf_bm (HttpOnly, Secure, about 30 minutes), for its bot management; it is set by Cloudflare, not by us, and we do not read or use it.

Who else sees your data

  • Your email provider and the mail service used to send sign-in links see your address and that a link was sent.
  • Website delivery: the pages of this website (not the hub itself) are delivered through DigitalOcean's App Platform, which serves them through Cloudflare's network. As with any web host, DigitalOcean and Cloudflare see the IP address and browser details sent with each page request.
  • GitHub, if you choose GitHub sign-in, sees that you signed in to this service.
  • GitHub (release check): the hub server itself contacts api.github.com once an hour to learn the newest public Coral release, so it can tell you when your machine is behind. It sends no user data, credentials, account or server information; GitHub sees only the hub's IP address and a coral-hub user agent.
  • The hosting provider: the hub runs on a single server at a commercial cloud provider, with an encrypted off-site backup copy at the same provider. Traffic and stored data are on their infrastructure. The provider and region are not yet listed here.
  • A certificate authority: the public certificate request for the hub's domain.
  • Operators of the hub have access to the database and to live traffic on the machine. That access is limited to the operators of the service; changes made through the Hub's operator commands are recorded in the operator log.

Who can see what, between users

Each account sees only its own servers and agents. The hub enforces this in the application and again in the database. Another user cannot list, open or launch anything on your servers.

Your choices

  • Each server starts in view-only mode. Typing into agents (interact) and starting agents (launch) are separate, per-server choices that also need the setting on the Coral server itself. Cross-team messaging between boards on a machine is off by default and both boards must opt in. It is turned on from that machine, per board, and cannot be turned on through Coral Hub at any access mode, Interact and Launch included. Once on, it lets agents on different boards of the same machine pass messages to each other.
  • Auto-accept: Turning auto-accept on for an agent requires Launch mode on that machine and the local switch in Coral's Settings. Turn it off at any time with Interact mode or from the machine itself. Auto-accept ends automatically when the time limit runs out, when the agent restarts or wakes, when access is lowered below Launch, or when the owner lowers the local maximum.
  • Team messaging is off until you turn it on, and each link is one-way and revocable. While it is off nothing is relayed between your servers, and your links are kept. Turning it on is a deliberate choice in Coral Hub; it needs a signed-in account owner. Messages between your servers need the receiving server to be set to Interact or higher.
  • Revoke any server from the Servers page at any time; its connection is closed immediately.
  • Sign out everywhere to end all browser sessions.

Deleting your account

During the closed beta, write to hello@subgentic.ai and we will delete your account and its data; encrypted backups age out within 30 days.
